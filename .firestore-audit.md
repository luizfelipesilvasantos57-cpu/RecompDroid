# Firestore data and access audit (prototype)

## Collections and schemas

- `users/{uid}`: private profile. Required: `displayName` (string, 1–60), `username` (ASCII letters/digits/dot/underscore, 3–24), `updatedAt` (timestamp). Optional: `photoBase64` (base64 JPEG, max 700,000 characters). Exact UID document read; merge writes.
- `users/{uid}/games/{slug}`: private playtime aggregate. Required: `title` (string, 1–160), `playSeconds` (integer, 0–315,360,000), `launches` (integer, 0–1,000,000), `lastPlayedAt` (timestamp). Owner-only list and merge writes.
- `users/{uid}/reviews/{gameHash}`: private owner mapping for an editable review. `gameHash` is a 64-character lowercase SHA-256 hex digest of the catalog slug. Required: `reviewId` (random 20-character Firestore ID), `rating` (integer, 1–5), `comment` (string, max 500), `updatedAt` (timestamp). Owner-only exact read and atomic batch writes.
- `games/{gameHash}/reviews/{reviewId}`: public projection containing only `rating`, `comment`, and `updatedAt`; it contains no UID, email, username, or profile fields. Guests may read; signed-in users can create/update only when a matching private ownership mapping is written in the same batch. Deletes are denied.

## Access patterns and queries

- Firebase Authentication email/password supplies the UID.
- Existing reads: get `users/{uid}`; list `users/{uid}/games`.
- Reviews: get `users/{uid}/reviews/{gameHash}`; list public `games/{gameHash}/reviews`, ordered by `updatedAt` descending and limited to 50; publish/update uses one atomic batch for private and public docs.
- No `where()` clauses or composite indexes are used. The review list uses a single-field ordering index.
- Both profile and play-progress data remain private to the matching UID. Review public documents use random IDs; no author identity is copied into them.
- Rules validate field sets, types, ranges, sizes, and the cross-document owner mapping for public review writes. Other paths default deny.

## Devil's-advocate review / limitations

- Public review text is user generated; a reviewer could include personal information or inappropriate content in the comment. There is no moderation/reporting or rate-limit backend in this release. The 500-character cap and one editable review per account/game reduce, but do not eliminate, abuse.
- A malicious authenticated client can submit arbitrary ratings/comments for its own review; client-side identity does not prove that a game was actually played.
- Client-reported playtime remains approximate and can be manipulated.
- Usernames are display labels and are not globally unique.
- Rules are a security prototype. Validate them in the Firebase Emulator and review them before broadly distributing the app.
